# SilkOS → bootable Linux ISO

## Build with GitHub Actions (recommended)
1. Create a new GitHub repo and upload everything in this folder (keep the `.github` folder).
2. Open the **Actions** tab → **Build SilkOS ISO** → **Run workflow** (takes ~15-25 min).
3. When it finishes, download the **silkos-iso** artifact (unzip it to get the `.iso`).
   If it fails, download the **build-log** artifact and send me the last ~60 lines.

## Test in VMware Workstation Pro
1. File > New Virtual Machine > Custom (advanced) > Next. Choose **"I will install the operating system later"**.
2. Guest OS: Linux > **Debian 12.x 64-bit** (or Debian 13 if listed). Firmware: BIOS (default).
3. 2 processors (1 core each), **4096 MB** memory, NAT network. For the disk, 20 GB is fine (it is never used by the live image).
4. Before starting: VM > Settings > Display > tick **Accelerate 3D graphics**, graphics memory 512 MB or more.
   CD/DVD > Use ISO image file > pick the SilkOS ISO. Make sure "Connect at power on" is ticked.
5. Power on. SilkOS starts by itself.
   - First boot: it uses software rendering (safe). To try the GPU, hit **e** / **Tab** at the boot menu and add `silkos.gpu`.
   - If animations stutter in software mode, switch on Lite Mode in Settings.

## Handy things
- Debug shell: Ctrl+Alt+F2, log in as `silk` / password `live`. Logs: `/tmp/silkos.log`, `/tmp/openbox.log`.
- Gestures do nothing? SilkOS reads them from libinput itself. Run `libinput debug-events` in a terminal (Ctrl+Alt+F2) and swipe three to five fingers: if lines like GESTURE_SWIPE_UPDATE appear, the touchpad works and `/tmp/silkos.log` will say why SilkOS is not seeing them; if you get "Permission denied", the udev rule or sudo fallback is not applying. A gesture completes after roughly 25 mm of swipe travel or a 22% change in pinch spread, so you should not have to stretch your hand across the trackpad. Virtual machines often do not pass multitouch through.
- A native app's menus never appear in the SilkOS bar? `echo $GTK_MODULES` in a terminal should contain `appmenu-gtk-module`, and the app has to use a traditional menu bar (see below). `/tmp/silkos.log` prints why the menu helper stopped. Square corners with no animations mean picom rejected `/etc/silkos/picom.conf`, which `/tmp/picom.log` says so.
- Boot-menu options (press Tab/e): `silkos.gpu` = allow GPU in a VM, `silkos.nosandbox` = Electron --no-sandbox.
- Run on any Linux desktop without the ISO: `./linux/run.sh`
- Build locally instead (Ubuntu/Debian machine with Docker): `npm install && npm run build:linux && ./distro/build-local.sh`

## What is real vs fake now
Real on Linux: Shut Down / Restart / Sleep (systemctl), battery (/sys), network status (nmcli), brightness (brightnessctl), output volume, and audio routing. Trackpad settings turn on tap to click and natural scrolling for every libinput touchpad (natural scrolling is on by default: content follows your fingers). Display & Sound scales the whole interface automatically or to 100/125/150/200%; SilkOS and native apps resize together, and Automatic reads the panel's pixel density (a 13" 2K laptop lands on 200%).
Screenshots: Shift+Super+3 grabs the whole screen and Shift+Super+4 lets you drag an area (Esc cancels, Return or the Save button saves); both the keys and the Apple menu work while SilkOS has focus. Each capture is copied to the clipboard and saved as a PNG in Pictures/Screenshots, and the banner that follows can open that folder in Finder. The area overlay freezes the screen before it appears, so an open menu is never photographed.
Notifications: alerts from the Store, low battery, Wi-Fi changes and captive portals appear as banners at the top right and collect in the clock's notification centre (click the clock). Do Not Disturb in Control Center silences the banners while still recording the notices, and shows a moon on the clock.
Finder is a file manager now: Home, Desktop, Documents, Downloads and Pictures in the sidebar, double-click to open, Shift/Ctrl-click for ranges and multiple items, arrow/Return/Delete shortcuts, inline New Folder and Rename, move items by dropping them on a folder or place, Move to Trash, hidden files, search, and sortable Name/Size/Date columns. Sizes and dates fill in just after a folder opens instead of making it wait, and writing is limited to your home folder (Computer still opens anywhere).
Sound in Control Center routes audio: the chevron on the Sound tile slides open an Output and an Input list from PipeWire/PulseAudio, marks the current device, and switching moves the players that were on the old device along with it. Wi-Fi adds a Join Other Network row (type the name, tick Hidden Network for a network that does not broadcast) and a sign-in banner with an Open button when NetworkManager reports a hotel/airport captive portal.
Finder browses files (including optional hidden files; double-click an .exe to run it with Wine). Terminal opens xterm. Notes supports folders, search, rich text, checklists, pinning, Trash and restore, export, and automatic local saving, and is laid out like the macOS app: one chrome strip across the top carries new folder, new note and delete, then the Aa style menu with bold/italic/underline, list, checklist and link, then pin, share and the search field; the sidebar lists All Notes, Pinned Notes, your folders and Recently Deleted with their counts; the selected row fills with the accent colour and dates read the way Notes does (the time today, Yesterday, the weekday inside the past week, then the date); and the editor puts the title over a centred "October 30, 2026 at 1:06 PM" line that names the folder only when the note is not in Notes.
Browser is a multi-tab webview browser with a Safari-style address field (the site name when idle, the full address while you type), suggestions from bookmarks, history and search-as-you-type, a Favorites start page, a tab overview that shows the last preview captured while each tab was on screen (and the page title for a tab that has never painted, because a hidden page captures blank), per-tab site icons, back/forward/stop controls that grey out when there is nothing to do, Find in page (Cmd/Ctrl+F) with match counts, a plain-language page when a site fails to load, links that open in a new tab, and bookmark/history import from a file.
SilkOS keeps its desktop shell visible across four Openbox desktops, because the whole desktop is one fullscreen window and the ISO's Openbox rules pin it to every desktop (the image build fails if that rule is missing); your app windows stay on the desktop where you opened them. Switch with Ctrl+Alt+Left/Right or a three- to five-finger horizontal swipe. A three- to five-finger swipe up fades in the window switcher, and a three- to five-finger swipe down exposes the desktop (click, press Escape, or swipe up to bring windows back), and Super+D does the same from the keyboard - the live image drops Openbox's own iconify-all binding for that key because it hid the window that paints the wallpaper and left a black screen. A three- to five-finger pinch in (thumb plus fingers) reveals Launchpad, and pinching out closes it, and the background blur, the dimming and the frosted panel behind the icons ramp up in step with your fingers, from a clear wallpaper to the fully frosted backdrop; opening Launchpad from the dock or the keyboard animates that same blur and fades the panel in with the tiles rather than switching it on. While it is open the Dock steps aside and the menu bar stays crisp, clickable and able to open its dropdowns, as on macOS. That panel is the icon grid itself: a rounded translucent card that hugs its rows, stays centred under the search field as you filter (a lone result or "No Results" shrinks it instead of leaving a full-width sheet), adds its own blur on top of the desktop-wide one, scrolls without a visible bar when the rows do not fit, and falls back to a flat lighter veil in Lite Mode. Shell animation timings share one scale (tap, menu, panel, spatial, window), so menus and popovers decelerate without bouncing while only things that physically land, such as the dock and new windows, settle with a slight spring. Every scroll area draws a macOS-style overlay bar instead of the stock Chromium one: a slim thumb tinted from the text colour inside a wider hit area, with no trough and no arrow buttons, so it stays light on dark panels and dark on light ones. Each gesture eases a filtered value rather than painting every discrete libinput step, the way macOS smooths trackpad input: a small movement moves the desktop, switcher or windows a small amount, and the view keeps settling toward the last finger position for a moment after the fingers stop. The decision to switch still uses the raw travel, so the gesture completes on release once the finger has crossed half the screen, or sooner on a flick, and pausing long enough at the end cancels the flick so the view settles back. While a desktop swipe runs, each window paints its glass from a scroll-attached copy of the same wallpaper rectangle, so the window and its background travel as one layer instead of the fixed background repainting every frame and phasing at the edges. SilkOS reads touchpad gestures straight from libinput (the `libinput-tools` package) and animates them itself; Touchégg is no longer used. Supported multitouch hardware is required, and virtual machines may not pass gestures through.
Right-click works everywhere: the desktop, the menu bar, Dock icons and the Dock background, Launchpad tiles and background, window title bars (Minimize, Zoom, Enter Full Screen, Move to Desktop, Close), Finder items, sidebar and background, and the Browser's tabs, address field, tab overview and page content. On a web page the menu offers Open Link in New Tab, Copy, Cut/Paste in fields, Back, Forward, Reload and Copy Page Address. The menus reuse the menu-bar dropdown styling, so they blur, fit on screen and close on the same outside click as the rest of the shell.
Saving (persistence): add a second empty virtual disk (8 GB or larger) to the VM, then Settings > Storage > Set up, and restart. Everything is kept after that. Installed Store apps appear in the dock and Launchpad.
All Openbox-managed desktop app windows (including Flatpak, Wine, and terminal apps) use the shared SilkOS dark title bar, with centered titles and the three colored controls on the left. Store-launched Flatpak apps disable GTK client-side decorations so they use the same SilkOS title bar. Picom matches SilkOS's rounded window corners to the display scale and adds soft shadows to normal app windows while leaving the fullscreen SilkOS desktop square. Store app icons keep their own transparent artwork: the dock, Launchpad and the Store's lists show the logo alone, with no coloured tile painted behind it. Dock magnification uses the macOS model: the bell is measured in icon slots rather than pixels and stops at a fixed radius, the dock slides so the icon you are pointing at stays under the pointer, and both the resting size and the peak cap to the viewport so the dock never grows past the screen. The icon under the pointer is always the tallest one, and the animation stops as soon as it settles.
Native app windows are themed to match the SilkOS page. The image installs the WhiteSur GTK theme (Light and Dark, translucent and solid variants), the WhiteSur icon set and the WhiteSur cursors, each fetched from a pinned release and checked against a checksum, then points GTK 2, GTK 3, GTK 4 and dconf/GSettings at them and uses the adwaita-qt style for Qt, so Flatpak, Wine and terminal windows get macOS-like colours, the traffic-light controls on the left, and the same Inter font. Stock picom 12.5 animates them with a config file rather than a patched build: normal windows fade and grow as they open, shrink and fade as they close, and minimising shrinks the window toward its own centre instead of bending it into the Dock, because picom has no way to know where the Dock sits. Openbox reserves the 28-pixel menu bar strip at the display scale so a maximised app window cannot cover it. GTK apps hand their menu bar to the desktop bus (appmenu-gtk-module with the canonical appmenu-registrar) and SilkOS draws it in its own bar while that app is the frontmost window, with the bold app name in front of it and submenus the app has not filled yet requested as you reach them. Only apps with a traditional menu bar export one, so libadwaita and header-bar apps keep their own menus, a Flatpak can only hand its menu out if its own runtime carries the module, and Debian trixie ships no Qt global-menu module, so Qt apps keep theirs too.
Store app: browses Flathub by category with a hero pick that changes daily, opens a real app page (screenshots, sanitized description, version, release date, license, developer, website/support links, and a Verified by Flathub note when upstream has verified it), and installs, updates, or uninstalls Flatpak apps per-user, so no password is needed and it works over the internet. Installs and updates are streamed from flatpak, so the button shows the stage name and a real progress bar instead of spinning, and the status line names the app and action as soon as you press the button and keeps a failure visible instead of quietly resetting, so a slow Flathub handshake cannot look like a dead button. An Installed list shows what you own with its version, and an Updates list compares each installed app with Flathub and offers Update All. Only one download or install runs at a time because flatpak locks its repository. App artwork and details are cached briefly, so switching categories does not re-request Flathub. Search goes to Flathub's HTTPS API directly, so results arrive with their own names and icons in one round trip instead of waiting for flatpak to download its app catalog; that download only happens for the Installed/Updates comparison, and not at all when you have nothing installed. Previewing the Store on Windows or macOS browses the catalog but cannot install. On the live ISO without persistence, apps you install live in RAM and are gone after a reboot. Installs, updates and removals announce themselves with a notification banner, so a download that finishes after you close the Store is not lost.
Control Center is a macOS-style tile grid: a connectivity card with Wi-Fi, Bluetooth and AirDrop rows, where tapping Wi-Fi or Bluetooth slides that radio's pane over the tiles - a back chevron, the radio's own on/off switch, a rescan button, the network you are on under Preferred Network and the rest under Other Networks with lock glyphs and four-bar signal meters, plus a password row when you pick a secured network - and the popover animates its height to the open pane instead of the full tile grid, so a short network list keeps a short window with nothing jumping under the pointer. The rest of the grid is a Do Not Disturb tile that springs its glyph when toggled, keyboard-brightness and Screen Mirroring mini tiles, full-width Display and Sound capsule sliders with an output mute button, a Now Playing card, and a Lock Screen action. The chevron beside the Sound slider opens the output/input routing pane, and the Wi-Fi pane adds hidden-network joins and the captive-portal sign-in banner. It also includes Wi-Fi and Bluetooth power controls and connecting from those panes, keyboard-backlight control when supported by the hardware, Do Not Disturb for SilkOS notification banners, and media-player controls: the Now Playing card shows what a native MPRIS player reports, and when there is no native player it shows what a Silk browser tab is playing (the video's own title with the site underneath, and Play/Pause sent back into that tab; previous and next stay greyed out because a web page has no queue to skip). The live image enables NetworkManager and BlueZ and includes the Wi-Fi supplicant, radio-control utilities and the non-free firmware for Intel, Realtek, Atheros, Broadcom and MediaTek wireless chips. AirDrop and Screen Mirroring are shown as unavailable in this Linux build. Settings includes desktop/dock layout, custom and built-in wallpapers, window behavior, keyboard switcher, accessibility, clock, Finder start folder/sorting/hidden-file/extension options, startup and app-session restore, audio, browser, security, and storage options. Alt+Tab cycles SilkOS windows and native app windows; Alt+Shift+Tab cycles in reverse.
Hardware support: besides the wireless blobs, the image includes AMD and Intel GPU firmware, Intel SOF audio-DSP firmware, Mesa for AMD/Intel graphics, Intel and AMD CPU microcode, and the VMware guest tools. NVIDIA cards run on nouveau with the `firmware-misc-nonfree` files; the proprietary NVIDIA driver is not part of the live image because the image does not build DKMS modules. Firmware packages have to be named in `distro/config/package-lists/silkos.list.chroot` because the ISO build turns off apt recommends, while the `non-free-firmware` archive area is already enabled.
The Apple menu, Control Center, and Settings > Security provide a SilkOS screen lock. Set a separate password in Settings > Security; any non-empty password is accepted (there is no 8-character minimum). The password is stored as a salted hash in the app's user data. This locks the SilkOS app window and does not replace the Linux account login.
