# SilkOS → bootable Linux ISO

## Build with GitHub Actions (recommended)
1. Create a new GitHub repo and upload everything in this folder (keep the `.github` folder).
2. Open the **Actions** tab → **Build SilkOS ISO** → **Run workflow** (takes ~15-25 min).
3. When it finishes, download the **silkos-iso** artifact (unzip it to get the `.iso`).
   If it fails, download the **build-log** artifact and send me the last ~60 lines.

## Test in VMware Workstation Pro
1. File > New Virtual Machine > Custom (advanced) > Next. Choose **"I will install the operating system later"**.
2. Guest OS: Linux > **Debian 12.x 64-bit** (or Debian 13 if listed). Firmware: BIOS (default).
3. 2 processors (1 core each), **4096 MB** memory, NAT network. For the disk, 20 GB is fine (it is never used by the live image).
4. Before starting: VM > Settings > Display > tick **Accelerate 3D graphics**, graphics memory 512 MB or more.
   CD/DVD > Use ISO image file > pick the SilkOS ISO. Make sure "Connect at power on" is ticked.
5. Power on. SilkOS starts by itself.
   - First boot: it uses software rendering (safe). To try the GPU, hit **e** / **Tab** at the boot menu and add `silkos.gpu`.
   - If animations stutter in software mode, switch on Lite Mode in Settings.

## Handy things
- Debug shell: Ctrl+Alt+F2, log in as `silk` / password `live`. Logs: `/tmp/silkos.log`, `/tmp/openbox.log`.
- Gestures do nothing? SilkOS reads them from libinput itself. Run `libinput debug-events` in a terminal (Ctrl+Alt+F2) and swipe three or four fingers: if lines like GESTURE_SWIPE_UPDATE appear, the touchpad works and `/tmp/silkos.log` will say why SilkOS is not seeing them; if you get "Permission denied", the udev rule or sudo fallback is not applying. Virtual machines often do not pass multitouch through.
- Boot-menu options (press Tab/e): `silkos.gpu` = allow GPU in a VM, `silkos.nosandbox` = Electron --no-sandbox.
- Run on any Linux desktop without the ISO: `./linux/run.sh`
- Build locally instead (Ubuntu/Debian machine with Docker): `npm install && npm run build:linux && ./distro/build-local.sh`

## What is real vs fake now
Real on Linux: Shut Down / Restart / Sleep (systemctl), battery (/sys), network status (nmcli), brightness (brightnessctl), and output volume.
Finder browses files (including optional hidden files; double-click an .exe to run it with Wine). Terminal opens xterm. Notes supports folders, search, rich text, checklists, pinning, Trash and restore, export, and automatic local saving.
Browser is a multi-tab webview browser with a Safari-style address field (the site name when idle, the full address while you type), suggestions from bookmarks, history and search-as-you-type, a Favorites start page, a tab overview with live page thumbnails, per-tab site icons, back/forward/stop controls that grey out when there is nothing to do, Find in page (Cmd/Ctrl+F) with match counts, a plain-language page when a site fails to load, links that open in a new tab, and bookmark/history import from a file.
SilkOS keeps its desktop shell visible across four Openbox desktops; SilkOS windows stay on the desktop where you opened them. Switch with Ctrl+Alt+Left/Right or a three- or four-finger horizontal swipe. A three- or four-finger swipe up fades in the window switcher, and a three- or four-finger swipe down exposes the desktop (click, press Escape, or swipe up to bring windows back). A three- or four-finger pinch in (thumb plus fingers) reveals Launchpad, and pinching out closes it, and the background blur and dimming ramp up in step with your fingers, from a clear wallpaper to the fully frosted backdrop; opening Launchpad from the dock or the keyboard animates that same blur rather than switching it on. Shell animation timings share one scale (tap, menu, panel, spatial, window), so menus and popovers decelerate without bouncing while only things that physically land, such as the dock and new windows, settle with a slight spring. Every swipe follows the finger one to one, so a small movement moves the desktop, switcher or windows a small amount; the gesture completes on release once the finger has crossed half the screen, or sooner on a flick, and pauses long enough at the end cancel the flick so the view settles back. SilkOS reads touchpad gestures straight from libinput (the `libinput-tools` package) and animates them itself; Touchégg is no longer used. Supported multitouch hardware is required, and virtual machines may not pass gestures through.
Saving (persistence): add a second empty virtual disk (8 GB or larger) to the VM, then Settings > Storage > Set up, and restart. Everything is kept after that. Installed Store apps appear in the dock and Launchpad.
All Openbox-managed desktop app windows (including Flatpak, Wine, and terminal apps) use the shared SilkOS dark title bar, with centered titles and the three colored controls on the left. Store-launched Flatpak apps disable GTK client-side decorations so they use the same SilkOS title bar. Picom matches SilkOS's rounded window corners to the display scale and adds soft shadows to normal app windows while leaving the fullscreen SilkOS desktop square. Store app icons retain transparent backgrounds so their logos blend into the dock. Dock magnification uses the macOS model: the bell is measured in icon slots rather than pixels and stops at a fixed radius, the dock slides so the icon you are pointing at stays under the pointer, and both the resting size and the peak cap to the viewport so the dock never grows past the screen. The icon under the pointer is always the tallest one, and the animation stops as soon as it settles.
Store app: browses Flathub by category with a hero pick that changes daily, opens a real app page (screenshots, sanitized description, version, release date, license, developer, website/support links, and a Verified by Flathub note when upstream has verified it), and installs, updates, or uninstalls Flatpak apps per-user, so no password is needed and it works over the internet. Installs and updates are streamed from flatpak, so the button shows the stage name and a real progress bar instead of spinning. An Installed list shows what you own with its version, and an Updates list compares each installed app with Flathub and offers Update All. Only one download or install runs at a time because flatpak locks its repository. App artwork and details are cached briefly, so switching categories does not re-request Flathub. Previewing the Store on Windows or macOS browses the catalog but cannot install. On the live ISO without persistence, apps you install live in RAM and are gone after a reboot.
Control Center is a macOS-style tile grid: a connectivity card with Wi-Fi, Bluetooth and AirDrop rows (each with a chevron that expands the same card into nearby-network or nearby-device panes), a Do Not Disturb tile that springs its glyph when toggled, keyboard-brightness and Screen Mirroring mini tiles, full-width Display and Sound capsule sliders with an output mute button, a Now Playing card, and a Lock Screen action. It also includes Wi-Fi and Bluetooth power controls and connecting from those panes, keyboard-backlight control when supported by the hardware, Do Not Disturb for SilkOS Browser toast notifications, and media-player controls when an MPRIS player is active. The live image enables NetworkManager and BlueZ and includes the Wi-Fi supplicant and radio-control utilities; usable wireless hardware and firmware are still required. AirDrop and Screen Mirroring are shown as unavailable in this Linux build. Settings includes desktop/dock layout, custom and built-in wallpapers, window behavior, keyboard switcher, accessibility, clock, Finder start folder/sorting/hidden-file/extension options, startup and app-session restore, audio, browser, security, and storage options. Alt+Tab cycles SilkOS windows and native app windows; Alt+Shift+Tab cycles in reverse.
The Apple menu, Control Center, and Settings > Security provide a SilkOS screen lock. Set a separate password in Settings > Security; any non-empty password is accepted (there is no 8-character minimum). The password is stored as a salted hash in the app's user data. This locks the SilkOS app window and does not replace the Linux account login.
